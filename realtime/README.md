# realtime

飛行中の風船の位置を、生の UDP で配る Go のサーバーです。WebSocket（Action Cable の `/ws`）に代わる配信の手段を試すためのもので、backend と同じ DB を読むだけです。風船を動かす計算は、今までどおり Ruby の風船移動バッチ（`balloons:move`）が行います。

## 起動

```sh
docker compose up -d realtime
```

`127.0.0.1:4000/udp` で待ち受けます。テストは `go test ./...` です。

| 環境変数 | 用途 | 既定値 |
| --- | --- | --- |
| `PGHOST`・`PGUSER`・`PGPASSWORD`・`PGDATABASE` | DB の接続先（pgx が読む） | なし |
| `ADDR` | 待ち受けるアドレス | `:4000` |
| `SPEED_SCALE` | 端末に伝える速さの倍率。backend と同じ値にする | `1` |

## 流れ

1. 端末が、購読のパケットに token を入れて送る
2. サーバーは token を `auth_tokens` と照合し、正しければ最新の snapshot をすぐに返す
3. そのあとは5秒ごとに、DB から読んだ飛行中の風船を snapshot として送る
4. 端末は20秒ごとに購読を送り直す。60秒届かなければ、サーバーは送るのをやめる

風船の位置は、風船移動バッチが DB を更新してから最大5秒遅れて届きます。snapshot は毎回すべての風船を送るので、届かなかったパケットは送り直しません。次の snapshot で取り戻せます。

## パケットの形

数値はすべてビッグエンディアンです。1パケットは 1,200 バイト以内です。

### 端末 → サーバー：購読

| バイト | 型 | 中身 |
| --- | --- | --- |
| 0 | u8 | `0x01` |
| 1〜 | UTF-8 | `POST /auth/login` などで受け取った token |

### サーバー → 端末：snapshot

風船が多いときは、いくつかのパケットに分けて送ります。どのパケットにも同じ見出しが付くので、1つずつ読めます。同じ snapshot のパケットは `seq` が同じです。

| バイト | 型 | 中身 |
| --- | --- | --- |
| 0 | u8 | `0x02` |
| 1〜8 | u64 | `seq`：送った時刻（Unix ミリ秒） |
| 9〜12 | f32 | 速さの倍率（`SPEED_SCALE`） |
| 13〜14 | u16 | 何番目のパケットか（0から） |
| 15〜16 | u16 | この snapshot のパケットの数 |
| 17〜18 | u16 | このパケットに入っている風船の数（最大49） |
| 19〜 | | 風船 × 数 |

飛んでいる風船がないときも、風船の数が0のパケットを1つ送ります。

風船1つは24バイトです。

| バイト | 型 | 中身 |
| --- | --- | --- |
| 0〜3 | u32 | 風船の ID |
| 4〜7 | u32 | 曲の ID |
| 8〜11 | f32 | 緯度 |
| 12〜15 | f32 | 経度 |
| 16〜19 | f32 | 東向きの速さ（m/s） |
| 20〜23 | f32 | 北向きの速さ（m/s） |

### サーバー → 端末：エラー

| バイト | 型 | 中身 |
| --- | --- | --- |
| 0 | u8 | `0x7f` |
| 1 | u8 | `0x01`：token が無効。ログインし直す |

## 注意

生の UDP には暗号化がないので、token は平文のまま流れます。
